# Audit remediation — control plane v1.1.1

This release applies the control-plane audit findings without changing the product's constitutional trading-safety model. The changes are control-plane definition/governance improvements; they do not grant runtime authority.

## v1.1.1 hardening pass

This patch release tightens the mechanical guarantees added in v1.1.0 after reproducing several cases where a nominally valid artifact could still encode an invalid lifecycle or misleading PASS.

- The empirical grader now fails when observations are complete but expectations fail; coverage and success are separate states.
- Skill telemetry enforces `invocation_started -> ... -> invocation_finished` and rejects both pre-start and post-finish events.
- The causal execution audit enforces `run.started -> ... -> run.completed` and rejects post-completion events.
- Definition verification now checks recorded schema version, exclusion metadata, and file count in addition to file digests and aggregate identity.
- Git UoW capture preserves both paths of rename/copy records and uses `intended_delta` rather than an authorization-sounding field.
- Effective-state compilation rejects tampered UoW records instead of accepting arbitrary JSON as Git-grounded evidence.
- Path-policy set identity is canonicalized over the target-path set, so discovery order does not change the compiled policy digest.
- `.pytest_cache/**` is treated as generated non-identity state and omitted from release packaging.
- The validator now has `--pre-snapshot` mode so edited definitions can be mechanically validated before a new immutable release identity is written; normal validation remains strict and requires the generated snapshot to match.
- Historical/durable `.codex/memory/**` runtime state is no longer selected for release archives. Immutable seed scaffolding lives under `.codex/control-plane/runtime-seed/**`, and `initialize_runtime_state.py` creates only missing runtime files without overwriting existing coordination history.
- `build_release_archive.py` packages exactly the verified definition snapshot plus its generated identity files, giving the distributable archive the same definition boundary as the control-plane release instead of silently carrying mutable state.

## P0 remediations completed

### Release identity

The stale `FILE_HASHES.sha256` model was removed. Release identity is now generated by `.codex/scripts/build_definition_snapshot.py` as:

- `.codex/control-plane/definition-snapshot.json`
- `.codex/control-plane/DEFINITION_HASHES.sha256`

Mutable `.codex/memory/**`, live Skill `telemetry/events.jsonl`, `.control-plane-state/**`, `__pycache__`, and `*.pyc` are explicitly excluded.

### Telemetry causality

Skill telemetry schema v2 now requires one `run_id` per invocation, contiguous sequence numbers, parent-event hashes, and event hashes. `skill_telemetry.py start` creates the run and `emit`/`finish` require reuse of that ID. Historical live telemetry is not packaged as release definition.

A separate `.codex/scripts/execution_audit.py` writes a hash-chained causal audit stream for observable run/snapshot/policy/authority/UoW/verification/effect events. This local stream is not represented as a substitute for off-host organizational audit.

### Behavioral authority

`AGENTS.md` no longer places current user intent above constitutional safety invariants. It separates behavioral authority from task specificity and explicitly states that task intent selects work inside the allowed envelope rather than enlarging runtime authority.

### Supervisor ownership

The former `phase-integrator` child supervisor was replaced by read-only `phase-router`. It returns a normalized task graph and never spawns, writes memory, or verifies. The primary agent/orchestration Skill remains the sole owner of spawn/wait/steer/adjudication lifecycle.

### External enforcement assumptions

`.codex/control-plane/enforcement-contract.json` now declares the externally required authority posture. `.codex/scripts/verify_enforcement_contract.py` evaluates supplied runtime/admin evidence and preserves missing evidence as `UNVERIFIED`. The contract explicitly does not grant permissions or approvals.

## P1 remediations completed

### Policy compiler semantics

`resolve_policies.py` is now `policy-resolver/v2`: it canonicalizes paths, rejects repository escape, preserves dot-prefixed paths, records policy content digests/matched patterns, and emits a deterministic `ResolvedPolicySet` digest.

### Effective-state compiler

`.codex/scripts/compile_effective_state.py` binds observable definition state to supplied runtime evidence. Missing model, capability, environment, authority, or UoW inputs are recorded as `UNVERIFIED`; repository prose is never used to infer them.

### Git Unit of Work

`.codex/scripts/capture_uow.py` captures Git baseline HEAD, branch, initial dirty state, intended delta, and a content-addressed UoW identity without mutating Git.

### Reviewer privilege split

Security finding/refutation is now a read-only `security-finding-reviewer`. Adversarial test writing is a distinct `security-test-author` role. `architecture-boundary-verifier`, `phase-router`, and `control-plane-verifier` are explicitly read-only. Read-only roles return evidence to the parent rather than widening authority merely to write memory.

### Executable evaluation contract

The 65 routing/task/failure cases are validated and mechanically gradeable with `.codex/scripts/control_plane_eval.py`. This does not turn corpus presence into empirical model evidence: actual Codex target-repository observations are still required before G5 can pass.

## Still external or unvalidated

The following are intentionally not claimed by this archive:

- actual Codex CLI behavioral trials in the target application repository;
- target application safety or structural inability to trade production;
- machine/workspace `requirements.toml`, permission-profile, approval, command-rule, network, credential, or MCP/app enforcement;
- authoritative off-host audit retention/OTEL/compliance correlation;
- actual runtime Tool/Capability and Environment snapshots unless supplied to the effective-state compiler.

Those boundaries preserve the core control-plane invariant: instructions influence decisions; policy authorizes effects; runtime executes; Git identifies change; governance explains observable evidence.
